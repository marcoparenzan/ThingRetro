# ThingNES architecture

New sources live under `ThingNES/src/ThingNES`, `ThingNES/src/ThingNES.Cli`, `ThingNES/src/ThingNES.Desktop` and `ThingNES/src/ThingNES.Tests`; the inner project folders were generated by dotnet new. `ThingNES/src/ThingNES.slnx` builds this slice independently. Existing machine projects are untouched.

`NesMachine` implements ThingRetroEmu's `IBus` and wires the reused ThingMOS CPU to cartridge, PPU and controller ports. Each machine tick advances one CPU (or DMA) cycle, one APU cycle and three PPU dots. The APU frame IRQ drives the CPU IRQ input; $4015 reads acknowledge it. $4016 remains the controller strobe, while $4017 writes select the APU frame mode. `Ricoh2A03` overrides a protected decimal-arithmetic capability on MOS6502; the default remains enabled for existing Commodore machines, including unofficial ARR. The shared core also exposes an overridable unstable LXA magic constant: MOS keeps $EE, while Ricoh uses the deterministic $FF model expected by the exercised Blargg suite. This does not claim one universal behavior for unstable silicon instructions.

`Cartridge` validates standard iNES NROM/UxROM/CNROM layouts before exposing memory. UxROM selects a 16 KiB bank at $8000 and fixes the final bank at $C000; CNROM switches 8 KiB CHR while PRG stays fixed. Power-of-two bank counts permit wired bank masks. Writes optionally AND the current ROM byte to model bus conflicts (default on); the CLI/API can override this for no-conflict board variants. This intentionally does not infer board variants from ambiguous iNES headers. `Ppu.Background.cs` implements v/t/x/w scrolling and a two-tile background pipeline with nametable, attribute and pattern fetch phases. Four 16-bit shift registers feed pixels through fine-X selection. Coarse X advances every eight fetch dots, Y advances at dot 256, horizontal t bits transfer at 257, and vertical t bits transfer on pre-render dots 280-304. Rendering-time PPUDATA accesses increment both axes. Read-only v/t/fine-X/toggle properties support diagnostics. `Ppu.Rendering.cs` combines background pixels with sprites and exposes a live palette-index framebuffer. `Ppu.Sprites.cs` clears secondary OAM on even dots 2-64, reads primary OAM on odd evaluation dots and copies selected bytes on even dots 66-256. It selects up to eight sprites for the following line, then fetches their pattern planes in separate phases over dots 257-320. Latched rows are promoted at the next visible line start; pixels no longer read live OAM or CHR. Read-only secondary OAM/count properties support diagnostics. Overflow scanning remains Y-only (no diagonal n/m bug); OAMADDR behavior/corruption, evaluation on pre-render, rendering-toggle races and exact mapper-visible bus signals are not modeled. `FrameImage` exports P6 PPM using an approximate fixed NTSC RGB palette; color emphasis is deferred. `Controller` owns strobe and serial shift state. The headless CLI uses Microsoft.Extensions.Hosting for DI, configuration and logging. The Windows-specific `ThingNES.Desktop` frontend is separate from the cross-platform core/CLI. It uses Microsoft.Extensions.Hosting for composition and logging, a double-buffered WinForms video control with the shared ARGB palette, and an 8 ms UI timer that polls a Stopwatch-based `FramePacer` targeting approximately 60.099 frames/s. Fractional frame credit is retained; catch-up is limited to three frames per poll and excess debt is dropped. All emulation, input and WAV callbacks run on the UI thread, avoiding concurrent machine access. Recording unsubscribes and finalizes on ROM replacement, power-cycle and disposal. `AudioPlayback` uses NAudio 2.2.1 `WaveOutEvent` (WinMM) and a 120 ms `BufferedWaveProvider` queue, discarding overflow and filling underruns with silence. PCM is submitted in 512-sample packets through a playback-only DC blocker/low-pass at half gain. Pause, ROM replacement and power-cycle clear queued audio and filter history; paused frame-stepping only records WAV, not live audio. WAV export remains raw/unfiltered. Wall-clock pacing is not audio-clock synchronized; hardware audio and UI behavior still require manual verification.

`DiagnosticRunner` advances the board within a bounded cycle budget and observes the Blargg text protocol through cartridge reads, not bus reads. It returns a typed outcome, optional ROM code, bounded message and elapsed cycles. `DiagnosticCommand` handles explicit local/HTTPS input and cancellation; synthetic 6502 programs exercise all outcomes offline. Reset requests stop execution rather than using the inaccurate inherited instantaneous CPU reset.

`Apu` owns NTSC timers, pulse duty/sweep/envelopes, triangle linear and length counters, noise LFSR, and a functional four/five-step frame sequencer. Sampling uses an integer phase accumulator against 1,789,773 Hz and a nonlinear pulse/TND mixer including the DMC DAC. It emits samples rather than retaining an unbounded buffer. `WaveWriter` writes PCM16 incrementally and patches RIFF sizes on disposal. Analog filters, anti-aliasing, held triangle DAC behavior and exact frame-register delays/IRQ races remain deferred.

`Dmc` separates memory reader state from its bit output unit. It exposes a pending address when its single-byte buffer is empty. `NesMachine` services this with a fixed four-cycle stall, reads through the CPU bus, and clocks PPU/APU throughout. In this functional arbiter DMC pauses OAM transfers; exact 3/4-cycle alignment, CPU write/RDY behavior, controller repeated-read glitches and startup/disable races are not modeled. DMC IRQ is separate from frame IRQ: $4015 reads only clear the latter, while $4015 writes or disabling DMC IRQ clear the former. $4011 DAC output persists even when playback is disabled.
