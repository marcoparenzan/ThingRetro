# ThingRetro architecture

## Common PAL/NTSC selection and Atari timing

`ThingRetroEmu.Video.VideoSystem` defines Auto/Ntsc/Pal. VideoPort stores explicit selection separately from detected source metadata and announces changes. Composite Auto uses that resolved system, falling back to refresh-rate detection when metadata is absent. Existing explicit composite PAL/NTSC encoding and native-composite source standards remain separate: cables do not change CPU clocks by themselves. The common VideoMenu exposes the console switch only when a machine opts in; the Atari Computer opts in, while Thing64 timing/defaults remain unchanged.

A78 TV byte 57 accepts NTSC $00 or PAL $01; unknown values remain rejected. The 7800 host publishes cartridge metadata to its common video port, defaults raw ROMs to NTSC, and uses the selected oscillator for pacing. Board wiring applies changes to MARIA and resets the machine when the effective system changes, including when MARIA is removed. MARIA uses 454 master clocks per line, 262/312 lines and provisional 242/292-line active crops. Master clocks are 7,159,092 Hz NTSC and 7,093,788 Hz PAL. AudioPort can change source rate while preserving speaker connection and discarding resampling state. POKEY still uses approximate per-slot clocks; queued PC audio and exact slow-slot timing remain limitations.

PAL palette is still the same approximate visualization, not a calibrated PAL palette. Active crop, DMA/DLI phase and PAL compatibility require external/manual validation. Switching system is not a promise that an NTSC game will work under PAL. Auto trusts metadata, not folder names. Tests cover selection, metadata, raster size/wrap, pacing, audio-rate changes, socket removal and invalid-load preservation.

## Post-render DLL acquisition and DLI overhead

At the last graphic line of a zone, six shutdown clocks acquire the successor DLL's three bytes from the live bus. The entry is cached for the following scanline; it is not fetched twice. If it requests DLI, MARIA emits NMI after acquisition and spends 17 additional master clocks under HALT. The graphic traversal budget is separate from this post-render overhead. Insufficient remaining time clamps overhead, records DliOverheadClampedLines and holds WSYNC to the boundary without falsely counting completed graphics as truncated. When even six acquisition clocks do not fit, successor acquisition is deferred to the following startup. No invisible successor is loaded after the final active line.

DliOverheadMasterClocks measures elapsed overhead clocks (not reserved clocks), and LastDliMasterClock records the edge. Reset/removal cancel pending overhead. The initial visible line bootstraps the DLL, renders its graphics and emits any initial DLI with 17 clocks of overhead. It does NOT decrement the zone offset, fetch a successor or pay shutdown on that line. Regular countdown begins on the next line, matching the `frame_scanline > 16` guard in archived MAME startdma. The initial offset consequently appears twice in the prepared line RAM; tests explicitly document that alignment. This removes the spurious pair of initial/successor requests within one HALT. No NMI queue or CPU latch modification was introduced. Eight-clock NMI width and electrical timing remain unvalidated.

DliTimingDiagnostic runs generated NTSC/PAL fixtures with or without startup DLI, records event clocks/raster/HALT and accumulates handler counts beyond byte wrapping. Two-frame matrix: NTSC 480/480 without startup, 482/482 with startup; PAL 580/580 without startup, 582/582 with startup. Minimum edge spacing is 452 clocks; zero unserviced requests, overhead clamps or truncations. The bootstrap plus final-line successor guard mean there are ActiveLines-2 successor transitions per frame, plus the optional initial DLI. CLI: `dotnet run --project src/CartridgeInspector/CartridgeInspector -- --dli-matrix ops/references/dli-matrix`. Exported raw ROMs and JSON measure this core, not independent hardware. Summer Games and Winter Games were re-executed for 180 frames with the known RAM corrections, zero truncations/clamps; gameplay and external timing remain unvalidated.

## Native 7800 two-button wiring

The existing generic ITwoButtonJoystick supplies Fire/Fire2 logical contacts; Fire2 does not consume a universal DigitalLines bit. The board maps P1 button 2/1 to TIA INPT0/1 and P2 button 2/1 to INPT2/3. These comparator inputs drive D7 high when pressed; lower open-bus bits remain intact. RIOT PB2/PB4 output-low selects native mode independently per port; output-high or undriven defaults to compatibility mode, where either button pulls INPT4/5 low. The existing VBLANK latch still applies to traditional fire inputs. This is a functional digital model, not potentiometer/capacitor simulation.

The TIA socket connects/disconnects optional ITiaButtonInputPinout. Computer enables the already available common simulator twoButtons option (Ctrl/Shift, keypad 0/Decimal, USB buttons 1/2); defaults for other machines remain unchanged. MAME riot_button_pullup_w/tia_r and BUTTONS declarations are the wiring reference. Eight new synthetic cases cover mapping, DDR/output changes, both ports, mirrors, D7/open bus, socket removal and absence of a universal second-fire pin. Windows inputs and real-game compatibility remain unvalidated.

## Common audio distribution and Computer recording

`AudioSplitter` implements ISpeaker: a single AudioCable drives same-rate destinations (PC speakers and WaveRecorder). Destinations are reference-deduplicated, explicitly disconnected before disposal, not owned by the splitter. Nested distributors/self-feedback and rate mismatch are rejected. Connection mutation and Play belong to the same emulation/UI owner thread.

Computer has Start WAV/Stop in the existing Peripherals and context menus, no toolbar. Muting speakers does not mute the WAV; recording is possible without a Windows audio device. Pause emits no samples. Stop, reset, cartridge replacement/ejection, video-standard changes and close finalize the RIFF header. Rejected ROM parsing leaves the recording intact. I/O errors in recording are reported with clipboard details and detach the recorder before continuing emulation. Recording start/stop is at common AudioPort block boundaries: a partial pre-start block can contribute, and the final partial tail (<10 ms) is not flushed. Manual Windows lifecycle verification remains pending.

## ThingNES.Computer alignment

Former ThingNES.Desktop is renamed ThingNES.Computer under ThingNES/src, including solution references. ComputerForm now uses common MonitorControl/VideoMenu, top Peripherals/Video and screen context menu, with no custom VideoPanel, toolbar or status/help strips. VideoMenu owns the connection to each NesMachine.Video, replaced/disposed on cartridge changes. NesMachine exposes a common AudioPort adapted from its existing APU PCM sample event; core timing/mappers remain unchanged. AudioCable -> AudioSplitter -> PcSpeakers/WaveRecorder replaces desktop-specific NAudio playback. Recorded UI output now includes common filter/gain; CLI raw WAV remains unchanged. FramePacer and NES keyboard serial-controller mappings remain intact. No shared DE-9 controller mapping is imposed on NES.

The API name NesMachine remains for compatibility: this increment does not rename it to Board or retrofit chip sockets. No NES WebComputer/Studio was created here. Three integration tests verify common video/audio cables and recording; GUI layout and audio interaction still require manual Windows comparison with Thing64.

## WebComputer / WebStudio

Two local Blazor Server hosts under ThingVCS7800/src share a Razor class library (`ThingVCS7800.Web`). WebSession and StudioCompiler are scoped DI services. Each circuit owns one DevelopmentComputer, generic joystick and a common MonitorCable connected to ThingRetroEmu.BufferedMonitor. The monitor pins a BGRA buffer only while alive; browser frames are copied/swizzled to RGBA. No machine-specific monitor/cable substitute is introduced. The ES module RetroMonitor only handles canvas, browser keys and Blob downloads; emulation and assembly remain C#.

Workbench provides Peripherals/Video organization, monitor and single-file Studio editor. This first browser UI is not pixel-identical to WinForms/Thing64's existing browser: server execution, Tailwind utilities and shared Atari components are deliberate. Run uses one frame per 100 ms with a 200000-slot watchdog, not real-time emulation. Async disposal cancels the pump, releases keys and JS references; scoped services dispose cables/pinned buffers. No audio browser transport yet.

StudioCompiler reuses ThingMOS.Assembler, validates source length, rejects file-reading and loop directive names, restricts output to $C000/16 KiB and creates legacy A78 v3 metadata. This conservative single-file gate is not a production compiler sandbox. No persistent project filesystem or authentication; local trusted use only. bUnit tests exercise Build and error rendering; xUnit tests cover load preservation, independent boards, compiler restrictions and actual cartridge execution. Browser/canvas interaction still needs manual validation.

## BIOS, INPTCTRL and 2600 development mode

Board has a removable IBootRomPinout socket. BootRom accepts externally supplied 4/16 KiB images mapped at the top of the 16-bit CPU space. No firmware is bundled/downloaded. HardwareBoot resets the control latch unlocked with BIOS reads enabled; ordinary direct-cartridge development boot stays locked in 7800 mode. BIOS read overlay does not swallow writes to the underlying cartridge. Unlocked TIA-window writes update INPTCTRL (MAME's alias behaviour); D0 locks until reset, D2 disables BIOS and D1 selects native 7800 rather than the functional 2600 mode. Other control bits/authentication/startup timing are not fully modelled. Bootstrap mode before the first control write uses native decode provisionally. A synthetic BIOS jumps to a RAM trampoline, disables its overlay and enters cartridge code, tested on the real board model.

2600 mode uses a 13-bit bus, A12 cartridge select, A7 TIA-vs-RIOT and A9 RIOT register-vs-RAM select. RIOT's 128 bytes supply zero page/stack mirrors. Linear 2/4 KiB cart class and explicit DevelopmentComputer.Insert2600 exist for development/tests. CPU uses six board master clocks, MARIA does not advance or drive HALT/NMI; TIA sound remains clocked. This is NOT playable 2600 emulation: TIA video/collisions/WSYNC, television timing, cartridge bank switching and PAL 2600 clocks remain incomplete. No generic A78/raw loader silently infers 2600 cartridges. Computer exposes BIOS install/remove in its existing Peripherals menu; 2600 insertion remains an explicit core API. Removing BIOS returns to direct 7800 boot. Invalid BIOS validation preserves prior firmware.

## POKEY peripheral pins and cartridge oscillator

`IPokeyPeripheralPinout` provides eight POT threshold inputs (conversion ticks, not ohms), a six-bit keyboard matrix contact callback with Shift/Control/Break, and external serial bit-clock methods plus output level. No Windows keyboard or real serial device is automatically connected to the cartridge. POTGO captures thresholds, counts to 228 and updates active-low ALLPOT; slow conversion uses 114 chip clocks per tick, SKCTL bit 2 selects fast conversion. Keyboard scan runs at 114 chip clocks per code; bit 1 enables scanning and bit 0 requires a repeated scan for debounce. This is a functional scanner, not all hardware rollover rules.

External serial clocks process 8N1 frames, SERIN/SEROUT, IRQ ready/complete/input and framing/overrun errors; SKREST clears errors without acknowledging IRQ. SKCTL break/reset are modelled. Internal serial clocks, asynchronous synchronization, two-tone and additional SKCTL behaviours remain unimplemented, exposed by `UnsupportedSkctlModes`. Complete status is preserved when IRQEN masks it. External clock methods are chip-level pins, not a claimed cartridge serial connector.

STIMER now resets counters four chip ticks after the write and does NOT clear pending IRQs. The delay is documented in MAME; exact phase validation remains pending (MAME itself annotates the delay implementation as FIXME). The existing aggregate joined counters and timer-overflow phases are not certified cycle-exact.

`IMasterClockedAudioCartridge` receives every board master tick. POKEY cartridge uses a rational accumulator for a configurable nominal independent oscillator (default 1,789,773 Hz), reset with cartridge reset. Thus PAL/slow CPU slots/HALT no longer implicitly change POKEY frequency. The nominal value is a configuration default, not a measured oscillator for every board. Legacy audio cartridges retain the four-master-clock TickAudio fallback. Common output resampling still follows the machine's clock; the independent chip stream is mixed at that sampling cadence. TIA two-phase/analogue validation remains separate and unfinished.

## Extended functional POKEY and TIA divider

POKEY now models 4/5/9/17-bit polynomial sources, poly5 gating, pure/volume-only output, AUDCTL base/fast clocks, joined 16-bit periods and CH3/4-clocked high-pass latches. Fast periods include +4 clocks; fast joined periods include +7. Joined low channels are not audible except volume-only. RANDOM samples the running 9/17-bit generator and reads inactive under SKCTL reset. Timer 1/2/4 IRQ flags and IRQEN/IRQST are provided by optional IPokeyInterruptPinout; reads do not acknowledge. STIMER restarts counters and clears flags in this functional model. Exact STIMER/IRQ transition phases need hardware validation. No cart IRQ wire was invented: chip IRQ is exposed but not connected to SALLY by the current cartridge socket wiring. Serial, keyboard, POT conversion and SKCTL extended modes remain absent; the reset low-two-bit handling and independent cart oscillator are still approximate.

TIA's frequency counter now compares AUDF and wraps at 31 when a new smaller value is written mid-count, rather than immediately truncating its period. Divide-by-three is a separate phase counter, and AUDC $0B supplies constant volume. Tests verify 15/31/511-step TIA noise repetition, mid-count AUDF changes, POKEY clock/join formulas, deterministic noise/RANDOM, filters and IRQ acknowledgement. This does not implement Stella's full two-phase TIA channel or analogue circuitry.

## Functional TIA audio

`TiaInputs` now contains `TiaAudio` and exposes optional `ITiaAudioPinout` through the existing TIA socket. AUDC0/1 ($15/$16), AUDF0/1 ($17/$18), AUDV0/1 ($19/$1A) are write-only with 4/5/4-bit masks. Two independent counters produce pure/divided tones and functional polynomial/gated noise; mode zero supplies volume-only output. Polynomial seeds/phases, internal two-phase clock and transitional behaviours are approximate, not Stella's cycle-exact model. LFSRs are computed rather than copied reference lookup tables.

Audio advances every master clock even during HALT. Base clock is master/228 (114 TIA colour clocks), independent of MARIA's 454-clock line. Every four master clocks the board clocks the partial POKEY cartridge and sends `(TIA + POKEY) / 2` to the existing AudioPort, including silence when no chips are present. This keeps the source rate fixed during slow CPU slots. Mixing is fixed headroom, not analogue resistor modelling; common AudioPort performs existing resampling/DC removal. POKEY still lacks its precise independent oscillator. Fire input read sampling does not advance sound. Reset resets both channels; unplugging the TIA socket removes its audio contribution. TIA video and analogue controller inputs remain missing. Manual Windows listening and external reference recordings have not been validated.

## Board address decoder

`BoardAddressDecoder` selects one socket/storage target plus offset, shared by reads, writes and slow-slot preview. TIA $0000–$001F and MARIA $0020–$003F ignore A8/A9 (four low-page aliases). RIOT $0280–$029F ignores A5/A6/A8; its internal 128-byte RAM is selected at $0480–$04FF and $0580–$05FF, not emulated as main-board RAM. TIA and both RIOT selects use the existing six-clock slow-slot model; MARIA/main RAM/cartridge use four clocks.

Low $0000–$01FF RAM aliases canonical $2000–$21FF except where low I/O selects overlay it. Canonical high RAM remains accessible independently. Main RAM $1800–$27FF is 4 KiB total. No general RAM mirror is fabricated at $2800–$3FFF: MAME documents revision-specific unreliable $2800 behavior. Missing chips return the held open bus and writes do not create hidden memory. Decode tests cover all 65536 addresses, every RIOT register mirror, RAM bounds/aliases and CPU slow-slot accesses. This is the 7800 development-mode map: BIOS overlay, control-lock and 2600 compatibility mode are still outside this increment; deeper stack entries that select I/O remain I/O, not guaranteed stack RAM.

## SALLY logical PHI1/PHI2 slots and bus handoff

SALLY exposes a side-effect-free next-cycle address/direction preview from the NMOS core. The board selects a four-clock normal or six-clock decoded TIA/RIOT slot before accessing memory. PHI1 is the first half, PHI2 the second; the CPU's single bus operation commits at the final PHI2 clock. SALLY samples NMI/SO on every master step while the instruction engine advances only on CPU cycles. The shared MOS6502 default Tick remains unchanged in behavior.

MARIA's new logical BusBoundaryInput pin is wired through its socket to CPU phase zero. It may acquire/release the bus at that boundary, not midway through a slow PHI2 operation. A boundary release recomputes the pending slow slot before PHI2; a DMA acquisition cancels CPU traffic and uses normal idle slots. Standalone MARIA retains its four-master-clock default boundary. This is a digital phase model, not electrical certification of SALLY clock stretching.

Tests compare previews against actual traffic for all 256 opcode starts, including page crossing and injected NMI, and verify that previewing changes neither registers nor memory. Board tests cover six-clock read/write edges, slow-cycle completion before DMA, pending slow access after release and socket disconnection. Existing 140 ThingMOS tests pass.

DLI reference review: archived `ops/references/mame-a7800-driver.cpp` implements dli_cb via pulse_input_line(INPUT_LINE_NMI, attotime::zero), i.e. a scheduler event, not a documented electrical pulse duration. `mame-maria.cpp` includes a 17-clock DLI overhead. The post-render 17-clock overhead is now modeled as described above; the eight-master-clock pulse and initial-frame timing remain provisional. No external DLI timing diagnostic ROM has been executed in this increment; synthetic IRQ/NMI/RTI regressions are not a substitute.

## MARIA/SALLY master-clock DMA sequencer

DMA no longer collects all reads at dot zero. At/after dot 28 it asserts DmaBusy on a four-master-clock phase and runs an iterator of delayed operations: DLL/header reads two clocks apart, map/graphics reads three clocks apart, 16-clock startup and bounded shutdown. Each read occurs against the live bus; no precomputed data or replay queue is used. Double line RAM remains: the previous buffer is displayed while DMA writes the next one. Normal completion releases the DMA hold on a four-clock phase; saturated traversal also uses WSYNC until the next line. Reset and bus removal cancel pending work. LastDmaClocks now reports measured occupied clocks, not a guessed future duration.

DLI is emitted after the new DLL entry's three bytes have been acquired, not at line start. The eight-master-clock pulse remains a provisional model; SALLY retains the NMI edge while HALT suppresses CPU bus accesses. Tests cover distributed fetch timestamps, live changes between graphic reads, phase alignment across scanlines, NMI during DMA, reset/removal, saturation and board CPU resumption.

Unlike the earlier aggregate-budget MAME approximation, the sequencer must allocate time to an indirect map read even when holey DMA suppresses the subsequent graphic read. Suppression tests now distinguish actual map traffic from omitted graphic traffic. The deadline reserves the last clock for completion and phase-aligned starts can shorten the available window. This is not yet hardware-cycle-exact: electrical validation of the logical 4/6-clock phases and handoff, DLI pulse width/startup behavior, DMA electrical timing and register races remain pending. Summer Games and Winter Games each completed 180 corrected-mapper frames with zero truncations; visual gameplay is not certified by this run.

## Atari 7800: functional MARIA line pipeline

MARIA now owns two 160-cell line-RAM banks. At each visible line start it swaps banks, clears and prepares the write bank from the display list, and outputs the previous bank. Thus the first visible line is backdrop and the first DMA result appears one scanline later. Palette and read-mode selection remain live at pixel output time. Both banks are cleared on reset and before the visible region to prevent previous-frame leakage. This buffer arrangement is now fed by the master-clock sequencer described above; exact hardware DLI/electrical timing remains unvalidated.

Synthetic tests cover the one-line delay, post-fetch graphics writes, live palette changes, reset and vertical-blank clearing. Existing graphic-mode tests now sample the buffered row. A 180-frame run of the attached Summer Games ROM still reports 22 truncated lines per steady-state frame; double buffering does not fix that counter and game compatibility remains unvalidated. The headless reproduction framebuffer is generated at `ops/references/summer-games-repro.ppm` using CartridgeInspector.

## ThingNES

New sources live under `ThingNES/src/ThingNES`, `ThingNES/src/ThingNES.Cli`, `ThingNES/src/ThingNES.Computer` and `ThingNES/src/ThingNES.Tests`; the inner project folders were generated by dotnet new. `ThingNES/src/ThingNES.slnx` builds this slice independently. Existing machine projects are untouched.

`NesMachine` implements ThingRetroEmu's `IBus` and wires the reused ThingMOS CPU to cartridge, PPU and controller ports. Each machine tick advances one CPU (or DMA) cycle, one APU cycle and three PPU dots. The APU frame IRQ drives the CPU IRQ input; $4015 reads acknowledge it. $4016 remains the controller strobe, while $4017 writes select the APU frame mode. `Ricoh2A03` overrides a protected decimal-arithmetic capability on MOS6502; the default remains enabled for existing Commodore machines, including unofficial ARR. The shared core also exposes an overridable unstable LXA magic constant: MOS keeps $EE, while Ricoh uses the deterministic $FF model expected by the exercised Blargg suite. This does not claim one universal behavior for unstable silicon instructions.

`Cartridge` validates standard iNES NROM/UxROM/CNROM layouts before exposing memory. UxROM selects a 16 KiB bank at $8000 and fixes the final bank at $C000; CNROM switches 8 KiB CHR while PRG stays fixed. Power-of-two bank counts permit wired bank masks. Writes optionally AND the current ROM byte to model bus conflicts (default on); the CLI/API can override this for no-conflict board variants. This intentionally does not infer board variants from ambiguous iNES headers. `Ppu.Background.cs` implements v/t/x/w scrolling and a two-tile background pipeline with nametable, attribute and pattern fetch phases. Four 16-bit shift registers feed pixels through fine-X selection. Coarse X advances every eight fetch dots, Y advances at dot 256, horizontal t bits transfer at 257, and vertical t bits transfer on pre-render dots 280-304. Rendering-time PPUDATA accesses increment both axes. Read-only v/t/fine-X/toggle properties support diagnostics. `Ppu.Rendering.cs` combines background pixels with sprites and exposes a live palette-index framebuffer. `Ppu.Sprites.cs` clears secondary OAM on even dots 2-64, reads primary OAM on odd evaluation dots and copies selected bytes on even dots 66-256. It selects up to eight sprites for the following line, then fetches their pattern planes in separate phases over dots 257-320. Latched rows are promoted at the next visible line start; pixels no longer read live OAM or CHR. Read-only secondary OAM/count properties support diagnostics. Overflow scanning remains Y-only (no diagonal n/m bug); OAMADDR behavior/corruption, evaluation on pre-render, rendering-toggle races and exact mapper-visible bus signals are not modeled. `FrameImage` exports P6 PPM using an approximate fixed NTSC RGB palette; color emphasis is deferred. `Controller` owns strobe and serial shift state. The headless CLI uses Microsoft.Extensions.Hosting for DI, configuration and logging. The Windows-specific `ThingNES.Computer` frontend is separate from the cross-platform core/CLI. It uses Microsoft.Extensions.Hosting for composition and logging, a double-buffered WinForms video control with the shared ARGB palette, and an 8 ms UI timer that polls a Stopwatch-based `FramePacer` targeting approximately 60.099 frames/s. Fractional frame credit is retained; catch-up is limited to three frames per poll and excess debt is dropped. All emulation, input and WAV callbacks run on the UI thread, avoiding concurrent machine access. Recording unsubscribes and finalizes on ROM replacement, power-cycle and disposal. `AudioPlayback` uses NAudio 2.2.1 `WaveOutEvent` (WinMM) and a 120 ms `BufferedWaveProvider` queue, discarding overflow and filling underruns with silence. PCM is submitted in 512-sample packets through a playback-only DC blocker/low-pass at half gain. Pause, ROM replacement and power-cycle clear queued audio and filter history; paused frame-stepping only records WAV, not live audio. WAV export remains raw/unfiltered. Wall-clock pacing is not audio-clock synchronized; hardware audio and UI behavior still require manual verification.

`DiagnosticRunner` advances the board within a bounded cycle budget and observes the Blargg text protocol through cartridge reads, not bus reads. It returns a typed outcome, optional ROM code, bounded message and elapsed cycles. `DiagnosticCommand` handles explicit local/HTTPS input and cancellation; synthetic 6502 programs exercise all outcomes offline. Reset requests stop execution rather than using the inaccurate inherited instantaneous CPU reset.

`Apu` owns NTSC timers, pulse duty/sweep/envelopes, triangle linear and length counters, noise LFSR, and a functional four/five-step frame sequencer. Sampling uses an integer phase accumulator against 1,789,773 Hz and a nonlinear pulse/TND mixer including the DMC DAC. It emits samples rather than retaining an unbounded buffer. `WaveWriter` writes PCM16 incrementally and patches RIFF sizes on disposal. Analog filters, anti-aliasing, held triangle DAC behavior and exact frame-register delays/IRQ races remain deferred.

`Dmc` separates memory reader state from its bit output unit. It exposes a pending address when its single-byte buffer is empty. `NesMachine` services this with a fixed four-cycle stall, reads through the CPU bus, and clocks PPU/APU throughout. In this functional arbiter DMC pauses OAM transfers; exact 3/4-cycle alignment, CPU write/RDY behavior, controller repeated-read glitches and startup/disable races are not modeled. DMC IRQ is separate from frame IRQ: $4015 reads only clear the latter, while $4015 writes or disabling DMC IRQ clear the former. $4011 DAC output persists even when playback is disabled.
